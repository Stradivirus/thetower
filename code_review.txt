  1. BACK (FastAPI 백엔드)
================================================================================

[ 잘 된 점 ]

  - Router → CRUD → Model 계층 분리가 깔끔함
    각 레이어의 역할이 명확하고, 책임이 섞이는 부분이 거의 없음

  - Read/Write DB 분리 (database.py)
    메인(쓰기) / 리플리카(읽기) 를 get_db / get_db_replica 로 분리
    실제 트래픽 고려한 현실적인 설계

  - fcntl 기반 스케줄러 잠금 (main.py)
    멀티 워커(Gunicorn 4 workers) 환경에서 크론 중복 실행 방지
    scheduler.lock 파일로 해결 — 실제 운영에서 겪은 문제를 해결한 흔적

  - report_queries.py 로 복잡한 SQL 분리
    비율 계산(CASE 문) 같은 복잡한 쿼리를 별도 파일로 격리해서 가독성 좋음

  - BattleDetail / V2 Cascade 삭제 설정
    ForeignKeyConstraint + ondelete='CASCADE' 로 부모 삭제 시 자식 자동 정리

  - 주석과 docstring이 충실함
    파일 상단 용도 설명, 함수별 설명이 잘 되어 있어 맥락 파악이 쉬움


[ 개선이 필요한 부분 ]

  ★ 보안 (즉시 수정 권장)

  1. SECRET_KEY fallback 위험 (auth.py:23)
     현재 코드:
       SECRET_KEY = os.getenv("SECRET_KEY", "secret_key_fallback")
     문제:
       .env 파일 없이 배포 시 고정값으로 폴백됨 → JWT 서명 키가 공개되는 것과 같음
       누구나 유효한 JWT를 위조 가능
     권장 수정:
       SECRET_KEY = os.getenv("SECRET_KEY")
       if not SECRET_KEY:
           raise ValueError("SECRET_KEY 환경 변수가 설정되지 않았습니다.")

  2. 비밀번호 최소 길이 4자 (routers/auth.py:30)

================================================================================
  2. DOCKER (인프라)
================================================================================

[ 잘 된 점 ]

  - 멀티 스테이지 빌드 적용 (frontend.Dockerfile)
    Node.js 빌드 → Caddy 서빙 분리로 최종 이미지 크기 최소화
    node_modules 가 프로덕션 이미지에 포함되지 않음

  - Caddy 도입으로 자동 SSL 처리
    Let's Encrypt 인증서 자동 발급/갱신
    Nginx 대비 설정 복잡도가 낮고 유지보수 쉬움

  - 보안 헤더 설정이 잘 되어 있음 (Caddyfile)
    X-Frame-Options, X-Content-Type-Options, HSTS, Referrer-Policy 모두 적용
    -Server 로 Caddy 버전 정보 숨김

  - 정적 자원 캐싱 전략이 올바름 (Caddyfile)
    /assets/* : max-age=31536000, immutable (1년 캐시, Vite 빌드 해시 기반)
    index.html : no-cache (새 배포 즉시 반영)
    Vite 빌드 전략과 정확히 맞아 떨어지는 설정

  - HTTP/3 (QUIC) 지원 (docker-compose.yml:38)
    443/udp 포트 열어서 HTTP/3 활성화

  - Gunicorn + UvicornWorker 조합 (backend.Dockerfile)
    --max-requests 1000 으로 메모리 누수 방지를 위한 워커 재시작 설정
    --max-requests-jitter 100 으로 동시 재시작 방지 (jitter 적용)


[ 개선이 필요한 부분 ]

  1. 백엔드 포트 미노출 (docker-compose.yml)
     backend 서비스에 ports 매핑이 없음
     Caddy 를 통해서만 접근 가능하므로 의도적인 것으로 보이나,
     개발/디버깅 시 직접 접근이 필요하다면 선택적으로 열 수 있도록 주석 안내 추가 권장
     예: # ports: ["8000:8000"]  # 개발 시에만 활성화

  2. 헬스체크(healthcheck) 설정 없음 (docker-compose.yml)
     restart: always 가 있지만, 컨테이너가 살아있어도 앱이 죽은 경우를 감지하지 못함
     권장 추가 (backend):
       healthcheck:
         test: ["CMD", "curl", "-f", "http://localhost:8000/"]
         interval: 30s
         timeout: 10s
         retries: 3

  3. Content-Security-Policy (CSP) 헤더 없음 (Caddyfile)
     XSS 방어를 위한 CSP 헤더가 설정되어 있지 않음
     게임 데이터 특성상 외부 이미지/스크립트 사용이 없다면 비교적 쉽게 적용 가능
     최소한 default-src 'self' 정도라도 권장

  4. POSTGRES_PORT 하드코딩 (docker-compose.yml:19)
     environment 에 POSTGRES_PORT: 5432 가 값으로 직접 적혀 있음
     다른 환경 변수들은 ${VAR} 형식인데 이것만 고정값
     일관성을 위해 ${POSTGRES_PORT:-5432} 로 변경 권장


  [ 총평 - Docker ]

  Caddy 선택이 이 프로젝트 규모에 딱 맞음.
  Nginx 대비 SSL 자동화와 설정 단순화가 실용적.
  캐싱 전략이 Vite 빌드 방식과 정확히 맞아 떨어져서 프론트 배포 최적화가 잘 됨.
  healthcheck 추가가 가장 실용적인 개선사항.
